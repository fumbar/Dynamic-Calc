## Findings, in priority order

### 1. Resolved for loopback hosting: the title selector left this fork

At the original audit, `index.html:191–237` hard-coded external calculator URLs and the
change handler navigated directly to them. The Unbound option pointed at the old site with
`m=insane`, `switchIn=11`, and the old identifier rather than `data=unbound`.

Consequences: choosing Unbound does not use this integration or its Expert default; choosing another title while hosting locally leaves the local application. Browser storage belongs to the origin, so the local imported box and settings do not accompany that navigation. The local redirect guard at line 1409 cannot help because the selector has already chosen an external destination.

Verified by inspecting the live dropdown's actual attributes. The existing other-title smoke check navigates directly to a local URL and therefore misses this workflow.

Recommended correction: route supported bundled titles to this fork's calculator entry point with their required parameters. Mark any intentionally external calculators explicitly. Do not mechanically turn decomp-only identifiers into local URLs: their data and mechanics need an actual supported local mapping.

Reviewed implementation: `localiseTitleOptions()` resolves IDs through `SOURCES` and
`backupFiles`, under `IS_LOCAL`. Decomp-only IDs remain external. This intentionally does
not extend to LAN/deployed hostnames, which retain inherited redirects and external routes.
The review added visible labels because `data-external` alone did not inform the user.
Expanded UI checks actually navigate Unbound → Renegade Platinum → Unbound, retaining the
origin and box selection and returning to Expert.

### 2. Resolved: tier changes discarded valid saved selections

`js/unbound_adapter.js:268–270` passes `localStorage.right` into `setExistsInTier()`. The stored value includes the species wrapper (`Floette (Lvl 19 Leader Mirskle)`); the helper at lines 280–288 looks for that entire string as a trainer-set key. Actual keys contain only `Lvl 19 Leader Mirskle`.

Live reproduction: the selected trainer exists in both collections. `setExistsInTier('insane', 'Lvl 19 Leader Mirskle')` returns true; passing its saved selection ID returns false. The tier handler consequently deletes both remembered selections even for a valid matching trainer. Box contents survive, but selection does not.

The other direction is also incomplete: opening a tier link directly bypasses the change handler, while `js/showdown_hooks.js:1461–1466` restores a saved opponent without checking membership in the loaded collection. That can restore an unavailable trainer label rather than a valid default.

Recommended correction: parse the full selection ID, validate the species and trainer-set pair against the corrected active collection at restoration time, and reset only invalid selections. Check a valid common trainer and a trainer absent from the destination tier.

Reviewed implementation: the raw-donor `setExistsInTier()` helper was removed.
`savedOpponentIsLoaded()` checks the species/set pair in the loaded `setdex`. Both completion
paths invoke it before restoration; the tier handler only navigates. UI checks verify a
shared trainer survives a tier change, a direct URL rejects an absent trainer, and a valid
opponent restores without requiring a left selection. Old line references above describe
the audited version; use the named helpers in the current code.

## Constraints affecting additional titles

These are inherited or explicitly retained limitations, rather than newly introduced regressions. They matter when deciding what “other ROM support” means.

- **Stock preservation is opt-in.** `loadDataSource()` calls `isolateWorkingTables()` only for `isolate_tables`. Live checks found `pokedex === calc.SPECIES[gen]` for Renegade Platinum, Blaze Black, Inclement Emerald, and Fire Red; Unbound uses a separate working object. Full-page navigation resets the JavaScript state, so this does not establish cross-navigation contamination. CONTEXT.md now describes this limit accurately. Same-document reload/reapplication is not an isolated title switch.
- **Custom move insertion is tied to generation 8.** Both insertion paths in `js/showdown_hooks.js:1019` and `:1204` write `MOVES_BY_ID[8]`, while existing-move overrides use `[g]`. A title using another species/move generation cannot assume a new UI move also exists in the engine lookup it uses. The handoff acknowledges this; it should be corrected and checked when supporting such a title.
- **Text import does not use the active species catalog.** `js/moveset_import.js:932–941` recognizes species through `calc.SPECIES[8]`. A species created only in the active title's working tables can be selectable in the calculator but skipped by import. Active-title lookup should precede a deliberate compatibility fallback before claiming custom-species import support.
- **The shared payload contract has implementation dependencies in the Unbound adapter.** `loadDataSource()` exposes generic keys, but isolation and field/tier initialization are implemented in `unbound_adapter.js`, loaded only by `index.html`. The tier control no longer reads `UNBOUND_DONOR` directly. The keys still are not a universally available multi-title API across HTML entry points. Move only genuinely shared helpers when a second consumer requires them; no schema framework is necessary.
- **False/zero move overrides are only partly handled.** The new flag mapping honors explicit false, but the older optional-property loop (`js/showdown_hooks.js:947–953`) still ignores zero priority and false `willCrit`/`secondaries`. No supplied-priority mismatch appeared in the five sampled title payloads. This is a contract limitation, not a demonstrated current battle error from this audit.

Existing title-specific save-reader gating hides direct save import for Unbound. Preserve this until an actual reader is implemented. Generic ROM extraction and arbitrary local JSON loading remain feature ideas, not existing support.

## What is clean enough to retain

- Donor data stays namespaced; corrections and tier payload construction are concentrated in the Unbound adapter.
- Unbound copies the mutable data tables before overriding them and preserves the donor collections.
- The mechanics delta is small, field flags survive cloning, and the Liquid Voice and `-ate` adjustments have explicit configuration switches.
- The harness follows the browser's unusual shared-exports module path rather than accidentally testing a different helper implementation.
- Existing text import and shared-box behavior are reused. No new schema, build system, or prediction implementation is needed to address the findings above.
